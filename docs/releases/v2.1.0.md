# HCS Discovery Studio v2.1.0

**Open science. Reproducible discovery. Made with ❤️ by hcsmedia.**

v2.1.0 is the first published version after the never-released `2.0.0` candidate.
It keeps the integrity work of that candidate (verified cache entries, heartbeated
leases, honest engine probes, measured ESOL) and adds compute that runs on the
machine you already have — and, for the first time, a path that needs no server at
all.

> Every number in this document comes from a report or a command in the
> repository. Where something is weak, it says so. Where something is not
> implemented, it is not listed as working.

## Highlights

### GPU similarity that is never silently wrong

- One WGSL kernel (`src/hcs_discovery/gpu/kernels/tanimoto.wgsl`) runs through
  `wgpu-py` on Vulkan, D3D12 or Metal, and through WebGPU in the browser.
- Integer popcounts are compared against the CPU reference before any result is
  returned; a mismatch raises instead of reporting a slightly different number.
- Similarity is `intersection / union` in float64, so values are bit-identical to
  RDKit's `TanimotoSimilarity`.
- Measured on this host's integrated AMD Radeon 680M: 500k fingerprints in ≈5 ms
  with the library resident (≈100 M Tanimoto/s), ≈19× RDKit's bulk call.
  Threshold searches use the BitBound prefilter (`min(a,b)/max(a,b)`), which skips
  32–88 % of a density-varied library and almost nothing on a uniform one — both
  rows are published in [`docs/validation/gpu-tanimoto.md`](../validation/gpu-tanimoto.md).

### The offline lab: the workbench without a backend

`/lab` imports CSV/SDF/SMI, computes descriptors with RDKit WebAssembly, applies the
same triage rules and weighted composite ranking as the server template, scores
Tanimoto similarity through WebGPU (or the labelled CPU reference), and keeps the
stored copy in IndexedDB on the device. A service worker caches the shell and the
WASM module, verified by killing the static server and reloading.

### Headless parity, now with more surfaces

- `hcs-discovery similarity search` and `POST /api/v1/similarity/search` return the
  same `hcs.similarity-search.v1` payload.
- `hcs-discovery mcp serve` exposes five read-only tools over JSON-RPC 2.0 with no
  new dependency.
- `hcs-discovery sat solve|select` solves DIMACS and chooses constraint-covering
  subsets with a dependency-free DPLL solver.

### Packaging that matches how people actually run things

- Wheel with the built SPA and the GPU kernel.
- One-file executable; its smoke test runs a verified GPU similarity search inside
  the frozen binary.
- Multi-stage Docker image (non-root, healthcheck, `HCS_DATA_DIR` volume).
- Static SPA deployment for the cloud, with per-route metadata, sitemap, robots and
  JSON-LD.

## Install

```bash
# Wheel
pip install hcs_discovery_studio-2.1.0-py3-none-any.whl

# One-file executable (Windows, built from source)
uv pip install "pyinstaller==6.22.3"
uv run python scripts/release/build_executable.py

# Container
export HCS_API_TOKEN=$(openssl rand -hex 24)
docker compose up --build
```

`hcs-discovery doctor` reports what the machine can actually do. `hcs-discovery
gpu probe` shows the adapter; `hcs-discovery gpu bench` re-measures parity and
throughput on your hardware.

## Known limitations

- Docking is regression-checked on one complex, not benchmarked.
- Property estimates are weak and carry no calibrated uncertainty.
- No MD, learned ADMET model or structure prediction.
- GPU execution exists for the Tanimoto kernel only; descriptors, docking and
  property estimates run on the CPU.
- SQLite and a local queue; no distributed workers or multi-tenant hosting.
- No TLS; a non-loopback deployment needs a proxy in front of it.
- The browser lab matches the server's *rules*, not its provenance manifest, and it
  says so on the page.

## Deployment status at the time of writing

The source and the wheel carry `2.1.0`. The hosted static build was **not** updated
with this version: the Vercel free-plan daily deployment limit
(`api-deployments-free-per-day`) was reached while preparing the release. The
previously verified deployment stays up and keeps working; it simply predates the
accessibility changes in this version. This is recorded rather than papered over.
