# HCS Discovery Studio 0.1.0 — preview

> Open science. Reproducible discovery. Made with ❤️ by hcsmedia.

This is the first public **preview** of HCS Discovery Studio, a local-first
workbench for reproducible computational drug-discovery workflows. It is a real,
tested vertical slice — not a complete discovery platform and not a validated
predictive system.

## What works in this release

- CSV, SDF and SMILES import with row-level outcomes, retained failures,
  duplicate retention, configurable standardisation and file checksums.
- RDKit descriptors, Morgan/Tanimoto similarity, explicit rule filters, Pareto
  fronts and a transparent weighted composite score.
- A persistent lease-based local queue with restart recovery, cancellation,
  per-node timeouts, content-addressed caching and at-least-once execution.
- Immutable run manifests with workflow snapshots, dataset and artifact hashes,
  engine versions, hardware description and limitations.
- Live run events, logs, cancellation, retry, artifact download and
  HTML/Markdown/JSON/CSV report export.
- A React UI covering the full demo path: project → import → workflow → run
  monitor → results → export, plus compound detail, model registry, settings and
  about pages.
- A headless `hcs-discovery` CLI and versioned `/api/v1` API backed by the same
  service layer.
- A self-contained wheel that bundles the built SPA, so the UI works without a
  Node toolchain.

## Install

The wheel is the supported artifact for this preview:

```bash
python -m venv .venv
. .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install hcs_discovery_studio-0.1.0-py3-none-any.whl
hcs-discovery doctor
hcs-discovery serve
```

Open <http://127.0.0.1:8787>. See the
[quick start](https://github.com/timfromhcs/hcs-discovery-studio/blob/main/docs/user-guide/QUICKSTART.md)
for the source checkout and the demo workflow.

## Verification

Local gates for this release: 82 backend tests, 3 Playwright end-to-end tests,
Ruff format/lint, mypy, frontend typecheck and production build. The release
workflow re-runs the backend suite for the tagged commit, builds the wheel,
generates a CycloneDX SBOM, writes SHA-256 checksums and attests build
provenance. Cloud CI results are linked from the commit and the Actions tab; the
release is published only from a green tag build.

Verify the downloaded assets:

```bash
sha256sum -c SHA256SUMS.txt
gh attestation verify hcs_discovery_studio-0.1.0-py3-none-any.whl --repo timfromhcs/hcs-discovery-studio
```

## Known limitations

- Only RDKit is a runnable scientific engine. Docking, molecular dynamics,
  learned property prediction and structure prediction are registry entries
  marked `planned`; they cannot be run.
- Workflows are linear single-input chains. Multi-input merges, branching,
  loops and parameter sweeps are not implemented.
- The queue and database target one local machine. There is no PostgreSQL
  deployment, distributed worker, multi-tenant isolation or hosted service.
- The local LLM provider is a configuration and health-probe surface, not a chat
  feature or an autonomous agent.
- No predictive-accuracy claim is made. The included validation protocol
  describes what would be required first.
- No telemetry, accounts, cloud dependency or Docker requirement.
