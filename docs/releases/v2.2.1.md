# HCS Discovery Studio v2.2.1

**Open science. Reproducible discovery. Made with ❤️ by hcsmedia.**

This is a release-pipeline fix, not a feature release. The application is
identical to `v2.2.0`.

## Why this version exists

`v2.2.0` was tagged on a commit whose CI and CodeQL runs were green, and its
release workflow passed the verification job, the wheel build and the one-file
executable build. The publish job then failed before it created anything:

```
Unable to resolve action `actions/download-artifact@3d3c42e5…`,
unable to find version `3d3c42e5…`
```

That commit does not exist in `actions/download-artifact`; the v7 line of that
action only has `v7.0.0`. The workflow now pins the resolvable v7.0.0 commit,
which matches the `actions/upload-artifact` v7 line it already used.

## What was and was not published

- **Not published for `v2.2.0`:** no GitHub release, no draft, no assets, no
  PyPI upload. The tag exists and points at a real commit; it is **not** moved,
  because this repository never reuses or moves a tag.
- **Published for `v2.2.1`:** wheel, CycloneDX SBOM, `SHA256SUMS.txt`, the
  one-file executable and the SLSA build provenance attestation.

## What you get over 2.1.0

The full content of `v2.2.0` — the whole workbench on Vercel (SPA and `/api/v1`
from one project), `HCS_DATABASE_URL`, `HCS_RUN_MODE=inline`, and the two
deployment fixes (the `src/` import path and the lazy `rdkit.Chem.Draw` import) —
see [`v2.2.0.md`](v2.2.0.md).

## Upgrading

`uv sync` locally, or install the 2.2.1 wheel. Nothing else changes.
