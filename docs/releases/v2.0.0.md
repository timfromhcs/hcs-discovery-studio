# HCS Discovery Studio v2.0.0 Stable

**Open science. Reproducible discovery. Made with ❤️ by hcsmedia.**

v2.0.0 is a correctness and integrity release. It keeps the v1.0.0 feature set
(CPU docking, property prediction, DAG workflows, connectors, agent, CLI, API,
desktop-class SPA) and removes paths where the software could report success
without evidence.

---

## Highlights in v2.0.0

### 🔐 Integrity instead of silent fallbacks

- **Cache entries are verified, not trusted.** Every entry records the table
  content hash and each artifact's SHA-256. Missing or modified artifacts force a
  re-run; incomplete entries are rejected.
- **Leases are heartbeated.** Long nodes renew their lease in the background, and
  a worker that loses its lease cannot write terminal run state.
- **Engine probes are honest.** AutoDock Vina is reported available only when the
  binary exits 0 and prints a recognisable version. The previous fabricated
  version string is gone.

### 🧪 Validation that can be reproduced

- **ESOL challenge benchmark.** The fabricated scaffold-test metrics were
  removed. The model now publishes measured performance on 45 independent,
  measured compounds curated by AqSolDB from the Llinas et al. (2008) Solubility
  Challenge: RMSE 0.968 log10 units, R² 0.072 (mean-baseline RMSE 1.004), with a
  bootstrap 95% CI of [0.708, 1.260].
- The report ships as `docs/validation/esol-solubility.md`, is regenerated by
  `scripts/science/validate_esol.py`, and a regression test recomputes every
  published number from the checked-in fixture.
- The `uncertainty` column is now labelled as a heuristic descriptor-distance
  error scale, not a calibrated confidence interval.

### 🧷 Stricter scientific semantics

- **Constraint objectives gate eligibility.** Constraint weights are forced to
  zero, constraint objectives are excluded from composite scores and the Pareto
  front, and results expose `constraint_pass` / `constraint_reasons`.
- **Joins cannot duplicate or overwrite silently.** `table.join` rejects
  duplicate right-side keys and suffix collisions.
- **Docking failures are per ligand.** `{prefix}_status` and `{prefix}_error`
  distinguish `docked`, `no_pose`, `invalid_input`,
  `ligand_preparation_failed` and `docking_failed`.

### 🛡️ Safer network and agent boundaries

- Connector redirects are blocked; 404 raises unless `allow_not_found=True`;
  malformed JSON becomes `ValidationError`; host allowlists normalise case,
  trailing dots, ports and IDNA.
- Agent plans are persisted with a digest. `run` requires a `plan_id` and rejects
  missing, mutated, reordered or tampered calls. Tool payloads reject unknown
  fields.

### ⚙️ Deterministic results

- Result counting, filtering, sorting and pagination execute in SQL, including
  JSON metric sorts, with `RunResult.id` tie-breaking and NULLs last in both
  directions.
- SSE streaming stops when the client disconnects instead of pinning a worker.

---

## Breaking changes

- Unknown workflow node config and agent tool payload fields are rejected.
- `table.join` raises on duplicate right keys and suffix collisions.
- Agent `run` requires `--plan-id` (CLI) or `plan_id` (API).
- Connector 3xx responses are errors; 404s raise unless explicitly tolerated.
- Constraint objectives no longer contribute to composite scores or Pareto
  ranking; they gate eligibility instead.

See `CHANGELOG.md` for the complete change list.

---

## Scientific caveat

> Computational docking scores, predicted physicochemical properties, and ranking
> indices are prioritisation signals for virtual screening, not experimental
> proof of binding, safety, or efficacy. The ESOL model explains little variance
> on the independent challenge set reported above; do not use its absolute
> predictions as measurements. All computational findings require wet-lab
> validation.
