# HCS Discovery Studio v2.2.0

**Open science. Reproducible discovery. Made with ❤️ by hcsmedia.**

v2.2.0 makes the hosted deployment the whole workbench. Until now the Vercel
project served the static SPA and the full application lived only on your machine.
The 500 MB Python function limit is no longer the reason to keep it that way: with
Vercel's Large Functions beta the same FastAPI app, RDKit included, runs next to the
SPA from the same origin.

Local-first is unchanged. Every new switch defaults to the local behaviour:
`HCS_DATABASE_URL` is unset, `HCS_RUN_MODE` stays `queue`, and the wheel, the CLI,
the container and the offline lab behave exactly as they did in 2.1.0.

> Every claim below was produced by a command against the deployment or by a test
> in the repository. Where the hosted instance is weaker than a local install, it
> says so.

---

## Highlights

### The full app on Vercel, one origin

- The root `app.py` is the entrypoint; the SPA is served by the application's
  existing catch-all route so the CSP, security headers and bearer-token rule
  apply to it as well.
- `VERCEL_SUPPORT_LARGE_FUNCTIONS=1` lifts the Python bundle limit from 500 MB to
  5 GB, which is what the RDKit dependency needed.
- Verified on the deployment: `GET /api/v1/health` → `{"status":"ok"}`,
  `GET /api/v1/ready` → `{"status":"ready","database":"ok"}`, and
  `GET /api/v1/projects` returns a demo project with **16 compounds and a computed
  triage run** — computed on that instance at start-up, not pre-rendered.
- `GET /` and `GET /lab` return the SPA shell; the client router still owns
  unknown paths.
- A workflow submitted with `POST /api/v1/runs` finished `succeeded` in **2.1 s**
  end to end (inline execution, §below).

### Runs without a worker process

A serverless function is frozen when the response is sent, so the embedded worker
thread cannot finish a run. `HCS_RUN_MODE=inline` makes the submitting request
claim **exactly the run it created** and execute it through the normal `Worker`.

Honest limits, in the CHANGELOG as well as here:

- It serialises work through the request. It is a preview/one-user mechanism, not
  a replacement for the queue.
- Once a run is claimed it runs to completion; `inline_run_budget_seconds` only
  prevents *further* attempts inside one request.
- A run longer than the platform's function duration is killed by the host, its
  lease expires and the normal stale-run recovery retries it.

### An external database when there is no disk

`HCS_DATABASE_URL` accepts any SQLAlchemy URL. The optional `postgres` extra uses
`pg8000` — pure Python and BSD-3-Clause, because `psycopg` is LGPL and the license
gate rejects it. Engine and session caches are keyed by URL now, so one process
can serve more than one database without sharing an engine.
`GET /api/v1/config` reports `database_backend` and never the URL, because a
Postgres URL carries a password.

### Two failures the deployment taught us

1. **`rdkit.Chem.Draw` needs a graphics stack.** The eager import pulled
   `libXrender` into *every* request and the whole API answered
   `FUNCTION_INVOCATION_FAILED`. It is imported lazily now; a host without
   `libXrender` gets a structured `424 missing_dependency` from the depiction
   endpoint only. Descriptors, similarity and ranking never touch it.
2. **A `src/` layout is not installed by the runtime.** Vercel installs declared
   dependencies but not the project itself, so `import hcs_discovery` failed. The
   entrypoint puts `src/` on the path; an installed wheel is unaffected.

## What this release does not do

- The hosted instance still keeps its SQLite database and its artifacts on
  `/tmp`. They are disposable and rebuilt per instance. Pointing
  `HCS_DATABASE_URL` at PostgreSQL makes the rows durable, but run artifacts
  (poses, CSVs, reports) are regenerable files and are **not** object-stored yet.
- No object storage, no Vercel Queues/Daemons worker, no users or roles beyond the
  existing static bearer token.
- The deployment stays behind Vercel Authentication. Making research data public
  is an owner decision, not an engineering default.
- Target-explorer UI, pocket detection, receptor preparation, MD, learned ADMET and
  structure prediction remain unimplemented, as listed in the implementation
  ledger.

## Upgrading

Nothing to do for a local install: `uv sync` and the defaults are unchanged.

For a hosted instance, the environment that was verified:

```
VERCEL_SUPPORT_LARGE_FUNCTIONS=1
HCS_DATA_DIR=/tmp/hcs
HCS_DEMO_MODE=true
HCS_RUN_MODE=inline
HCS_NETWORK_POLICY=local
HCS_WEB_DIST=/var/task/apps/web/dist
```

Add `HCS_DATABASE_URL` to move the state to PostgreSQL, and drop
`HCS_DEMO_MODE` only when you have a real workspace and a persistent database.
