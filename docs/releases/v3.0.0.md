# HCS Discovery Studio 3.0.0

*Open science. Reproducible discovery. Made with ❤️ by hcsmedia.*

This is the first major release after `2.0`. It is about closing measurable gaps rather
than adding model cards: similarity search now prunes without losing exactness,
provenance leaves the application in a format other tools understand, the MCP server
speaks the current specification, the property benchmark is measured on the full
published dataset, and release artifacts exist for every desktop platform.

Everything below was executed on the development host (Windows 11, Ryzen 7 7735HS,
Radeon 680M) and, where marked, in CI. Numbers that could not be measured are labelled
as open, not estimated.

## Highlights

### Exact k-nearest search that does less work

`TanimotoIndex.knn_hits` orders the library by popcount distance from the query, takes
the running k-th score as a lower bound, and stops scoring rows that cannot reach it.
The ranking is identical to a full scan (differential tests, ties included). The first
implementation dispatched one kernel per popcount ring and was measured **14× slower**
than a full scan — that version is not shipped. The staged implementation:

| Library | k | Rows scored | Bound-pruned | Full scan | Speed-up |
|---|---|---|---|---|---|
| 100k clustered | 10 | 10.3 % | 8.2 ms | 49.3 ms | **6.0×** |
| 500k clustered | 10 | 15.1 % | 69.6 ms | 267.7 ms | **3.9×** |
| 100k unclustered | 10 | 90.1 % | 60.6 ms | 51.7 ms | 0.85× |

The last row is the honest case: without clustering the bound prunes little and the
bookkeeping costs a little. The report says so. `--output` (a full score list) still
uses the full scan.

### Batched multi-query kernel

Sixteen queries are scored against one resident library in stacked dispatches, with
every count checked against the CPU reference. The table is kernel-level; the CLI
verifies every query against the CPU, so its wall time is higher:

| Library | Single-query total | Batched | Speed-up |
|---|---|---|---|
| 100k | 749.8 ms | 69.0 ms | **10.9×** |
| 500k | 3,758.7 ms | 387.3 ms | **9.7×** |

New command:

```bash
hcs-discovery similarity screen --queries queries.smi --file library.csv --k 10
```

### Provenance as RO-Crate

Every run can be exported as a ZIP with `ro-crate-metadata.json` (RO-Crate 1.1
context), the run as a `CreateAction`/`prov:Activity`, the workflow as a
`prov:Plan`, the software and execution environment, and every artifact with its
SHA-256. Missing artifacts abort the export. It is deliberately **not** labelled as
Workflow Run RO-Crate conformant: per-step actions are not emitted yet.

```bash
hcs-discovery report export <run-id> --format ro-crate --output run.crate.zip
```

The run monitor has the same export as a button, and the API exposes
`GET /api/v1/runs/{id}/export/ro-crate`.

### MCP 2026-07-28

The stdio server is dual-era: modern clients call `server/discover`, send
`io.modelcontextprotocol/protocolVersion` in `_meta`, and receive `resultType:
"complete"`, `ttlMs`/`cacheScope` and `structuredContent`. Unsupported versions get
`-32022` with the supported list. The legacy `initialize` handshake still works, so
existing clients keep running; both paths are covered by tests.

### ESOL, measured on the published set

The shipped Delaney equation is now reported on the full 1,128-molecule set:

| Set | n | RMSE | R² | Constant baseline |
|---|---|---|---|---|
| Full Delaney | 1,128 | 1.099 [1.047, 1.154] | 0.725 | 2.096 |
| Held-out scaffold split | 226 | 1.201 [1.076, 1.325] | 0.640 | 2.002 |

The 45-molecule drug-like stress set (R² 0.07) is still published next to it, because
hiding the weak case would be the opposite of the point. This is a reproduction of a
published equation, not a new model and not SOTA.

### Release on every platform

The release workflow builds and smoke-tests one-file binaries for **Windows x64**,
**Linux x64**, **macOS arm64** and **macOS x64**, publishes the container image to
GHCR and runs a health check against it, and attests every artifact. The wheel and
SBOM are published with SHA-256 checksums. PyPI publication stays behind the
`PYPI_PUBLISH` repository variable and Trusted Publishing.

## Upgrade notes

- Database migrations are unchanged; `hcs-discovery db upgrade` is still the step.
- `similarity search` results are identical; the pruning only removes work.
- MCP legacy clients need no change. Modern clients should call `server/discover`.
- The ESOL metadata changed (`version` 2.0.0, new benchmark keys). Anything that
  pinned `1.2.0` should read the new keys or the generated report.

## Known limitations

- No multi-target docking benchmark; the 1IEP redocking gate remains a regression
  test, not an accuracy claim.
- No learned ADMET model; ESOL is a published linear baseline.
- No ANN index. Exact search with bounds keeps recall at 1.0, and the 2020 indexing
  benchmark found exact bounded search competitive at perfect recall.
- The RO-Crate export is not validated against the Workflow Run RO-Crate profile.
- PostgreSQL is still not exercised against a real server.
- Uploads and run artifacts on the hosted deployment remain ephemeral.
