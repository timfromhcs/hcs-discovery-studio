# HCS Discovery Studio 3.0.1

*Open science. Reproducible discovery. Made with ❤️ by hcsmedia.*

This is the first **published** 3.0 release. The feature set is the one described in
the [3.0.0 notes](v3.0.0.md); this patch exists because the 3.0.0 tag could not be
published.

## Why 3.0.1

`v3.0.0` was tagged on a commit whose CI and CodeQL runs were green. The release
workflow then failed in the macOS x64 binary job before any release was created:

```
error: Distribution `rdkit==2026.9.1` can't be installed because it doesn't have a
source distribution or wheel for the current platform
hint: ... rdkit only has wheels for manylinux aarch64/x86_64, macosx_11_0_arm64,
win_amd64
```

RDKit does not publish a macOS x86_64 wheel, so an Intel-Mac binary cannot be built
from the locked dependencies. The repository never moves a tag, so `v3.0.0` remains
unpublished and `3.0.1` is the first release with the corrected matrix.

## Release targets

| Platform | Artifact |
|---|---|
| Windows x64 | `hcs-discovery-windows-x64.exe` |
| Linux x64 | `hcs-discovery-linux-x64` |
| macOS arm64 | `hcs-discovery-macos-arm64` |
| Container | `ghcr.io/timfromhcs/hcs-discovery-studio:v3.0.1` |
| Python | `hcs_discovery_studio-3.0.1-py3-none-any.whl` (PyPI gated) |

macOS x64 is **not supported** by the current dependency stack; this is an external
wheel constraint, not a tested-and-rejected claim.

## Verification

The same gates as 3.0.0: local `G0–G17` (including PostgreSQL and Lighthouse), CI on
Windows and Linux including the Vina redocking gate and Playwright, CodeQL, and the
release workflow's own wheel/binary smoke tests, checksums and build-provenance
attestations. The exact asset hashes are in the release's `SHA256SUMS.txt`.
